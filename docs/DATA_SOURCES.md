## 值得纳入的“穷鬼”场景

首版关键词由服务端固定维护，分类是发现线索，不是低价证明：

- 量贩零食：赵一鸣、零食很忙、零食有鸣、零食折扣。关注每 100 克价格与按需购买。
- 硬折扣/临期：好特卖、嗨特购、奥特乐、折扣超市。保质期、包装完整和实际吃完时间比原价标签更重要。
- 生活百货：名创优品、三福、十元店、平价百货。它们属于候选品牌，应比较同规格单价，不能一律称为最低价。
- 生鲜：菜市场、农贸市场、生鲜折扣。未来可引入临近收摊、时令蔬菜和社区小店线索，但门店是否有收摊折扣必须单独有证据。
- 日常餐饮：沙县小吃、兰州拉面、社区食堂、蜜雪冰城。未来可纳入工作日午饭、早餐、烘焙晚间折扣等带时段的具体价格。
- 活动：霸王餐、打卡赠品、限时特价。必须拆开抽签、抢名额、新客、最低消费、预约、发帖和有效门店；中奖概率未知时不计算“预期省下多少钱”。

## 现有数据模型

`Store` 包含 POI ID、名称、类别、地址、GCJ-02 坐标、来源及可选价格线索。`price` 是有说明的单品参考价，不是人均；真实 POI 当前不填写。演示门店带 `demo-` 前缀并以坐标隔离不同城市。

`Deal` 关联门店 ID，包含活动类型、领取价、额外最低消费、是否抽签、参与条件、截止时间、原始链接、创建时间及来源。`local` 均是当前设备保存的未核验线索，不能升级为“平台已验证”；`demo` 仅用于演示。

预算筛选时，未知价格不会被当成 0 元。有符合条件的活动时，可以使用活动最低参与成本。过期活动不参与结果、标记或排序；链接筛选只证明有链接，不证明链接内容、商家或活动真实。

## 后续平台接入的完成条件

1. 确认可以展示给本产品用户的授权范围与对应接口，拿到接口文档和可验证的测试返回，不能仅凭平台名称制作“已接入”按钮。
2. 将门店映射到高德 POI，保留原始平台门店和活动 ID，避免同名不同店串联。
3. 共享活动库需有审核、来源记录、更新时间、截止时间、撤回、过期及库存/资格未知状态；浏览器本地投稿不能冒充共享社区。
4. 对“免消费”“无需抽签”逐条按源规则核验；没有明确条件的活动应留为未知，而非推断免费。
5. 在真实大陆网络、真实设备上验收地图加载、定位、门店查询、实际可访问的活动原页以及失败重试，再考虑对外发布。

现阶段只完成前端交互、代理和查询代码、本地线索与测试。以上是下一阶段的依赖和验收条件，没有创建定时抓取或跨平台后台。
